# Практическая работа 6 Веб-сервер и автоматизация доставки

## Результат
Статический сайт размещается через Nginx по HTTPS. Запросы к HTTP перенаправляются на HTTPS, а пользовательские файлы доставляются отдельным сценарием `scripts/deploy.sh`.

## TLS и безопасная конфигурация
Для HTTPS используется самоподписанный сертификат с SAN. Закрытый ключ хранится только на сервере с ограниченным доступом и не добавляется в репозиторий. Перед применением изменений нужно проверить конфигурацию Nginx и выполнить безопасную перезагрузку службы.

## Доставка
Сценарий проверяет наличие главной страницы и чистое состояние Git, поддерживает пробный запуск `--dry-run`, передаёт содержимое через rsync и проверяет HTTPS-ответ. Перед запуском задаются параметры целевого сервера, каталога, URL и сертификата через переменные окружения. Это позволяет использовать сценарий без публикации адресов, учётных записей или путей конкретной машины.

## Проверки
`scripts/audit.sh` проверяет настройки SSH и межсетевого экрана, активность Nginx, синтаксис его конфигурации, срок сертификата, права каталога сайта и закрытого ключа. Переменные `TLS_CERTIFICATE`, `SITE_ROOT` и `TLS_KEY` задаются в окружении перед запуском.

Docker Engine и плагин Compose устанавливаются из официального репозитория Docker для Ubuntu. Участие в группе docker даёт полномочия, эквивалентные root. После добавления пользователя в группу нужна новая сессия.

В каталоге `app/` находятся Flask-приложение, Dockerfile, зависимости, Compose, .dockerignore и .env.example. Dockerfile использует python:3.12-slim, отдельного пользователя app, кэширование установки зависимостей и CMD в exec-форме. Приложение отвечает на /health и ведёт счётчик посещений в PostgreSQL.

Перед запуском скопируйте `.env.example` в `.env`, задайте собственный пароль PostgreSQL вместо change_me и выполните `chmod 600 .env`. Файл .env исключён из Git и контекста сборки. При доставке rsync используйте --exclude=.env.

Запуск из каталога app: `docker compose up -d --build`. Compose запускает приложение и postgres:16-alpine в сети backend, ожидая healthcheck базы. Приложение опубликовано только на 127.0.0.1:5000; порт PostgreSQL 5432 не публикуется. Именованный том db_data сохраняет данные после docker compose down; down -v удаляет том вместе с данными.

Для доступа через HTTPS в существующий блок Nginx добавляется location /app/ с proxy_pass http://127.0.0.1:5000/ и заголовками Host, X-Real-IP, X-Forwarded-For и X-Forwarded-Proto. Перед применением: nginx -t, затем reload службы. При остановленном приложении ожидается HTTP 502. После проверки создаётся снимок 05-docker-compose.

Раздел [5] сценария audit.sh проверяет службу Docker, состояние healthy контейнера сервиса db, привязку портов и права файла окружения. Дополнительно к параметрам проверки HTTPS задайте APP_DIRECTORY — абсолютный путь к каталогу Compose на сервере. APP_ENV_FILE при необходимости переопределяет путь к .env (по умолчанию APP_DIRECTORY/.env).

Этот PR переносит ранее выполненную совместную работу в личный репозиторий; развёртывание на учебной VM при переносе повторно не выполнялось.
